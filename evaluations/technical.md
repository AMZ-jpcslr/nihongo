# 技術文書の検証

README、API仕様、障害報告、設計メモ、PRの説明、コードレビュー、運用手順、論文の要旨、お客様への返信メールなどで、nihongoを確かめた記録です。

## やり方

- 課題を直したのは、どの比較でも同じAI（Claude Sonnet）です。比べる方法ごとに別々のAIに渡し、それぞれ自分の方法しか読めないようにしました。
- 判定したのは、直したAIとは別のAI（Claude Opus）です。2つの案をXとYに並べ替え、どちらがどの方法かを伏せて判定させました。
- 判定するAIには、課題ごとに「変わってはいけない点」の一覧（`tasks/technical/*/checklist.md`）を渡しました。1つでも崩れた案は、読みやすくても負けにしています。
- 「直しすぎの検査」の課題も入れています。もう読める文で、ほとんど変えないのが正解の課題です。

課題は4組あります。`dev` はルールを直しながら使った組で、`holdout-1`〜`holdout-3` は、その時の版のルールを決めた後に新しく作った組です。`dev` の結果は、ルールがその課題に合わせて作られている分、良く出やすいので、`holdout` の結果も合わせて見てください。

## 強化前の版との比較

強化前のnihongoと、技術文書の資料を強化した版を比べました。

| 回 | 課題 | 強化した版 | 強化前 | 引き分け | 意味が崩れた数（強化前 / 強化した版） |
|---|---|---|---|---|---|
| 1 | 7題 | 4 | 0 | 3 | 1 / 0 |
| 2 | 6題 | 5 | 1 | 0 | 1 / 0 |
| 3 | 6題 | 6 | 0 | 0 | 4 / 0 |

強化前の版で崩れた所の例：

- 「次回の報告は18時までに行う予定です」を「行います」と言い切った。
- 「現時点で個人情報の流出は確認されておりません」から「現時点で」を落とした。
- 「最大5回まで再試行し、それでも失敗した場合」を「5回失敗したジョブは」にして、回数がずれた。

## スキルを使わないAIとの比較

同じAIに、スキルを何も読ませずに直させた結果と比べました。この比較で、強化した直後の版（v10）は負けていました。直しすぎを避けるルールが強すぎて、直すべき硬い言い回しや形まで残していたためです。そこを直したのがv11とv12です。

| 版 | 課題 | nihongo | スキルなし | 引き分け | 意味が崩れた数（nihongo / スキルなし） |
|---|---|---|---|---|---|
| v10 | dev 16題 | 6 | 10 | 0 | 0 / 1 |
| v11 | dev 16題 | 10 | 6 | 0 | 0 / 0 |
| v11 | holdout-1 6題 | 2 | 4 | 0 | 2 / 0 |
| v12 | holdout-2 6題 | 4 | 2 | 0 | 0 / 0 |
| v12 | holdout-3 6題 | 3 | 3 | 0 | 1 / 0 |
| v12 | dev 16題 | 9 | 5 | 2 | 0 / 0 |

v11が新しい課題で崩した2か所（「各自で修正申請を行う必要がある」を「修正申請をお願いします」に弱めた、「必須ではない」を「不要」にした）を受けて、v12では「必須ではない」と「不要」、「必要があります」と「お願いします」を別の強さとして扱う決まりを足しました。

v12でもまだ残っている崩れ方は、Slackの「実施させていただく予定となっております」を「実施します」と言い切った1件です。予定を確定の言い方に変えてしまう癖は、次に直す点として残しています。

スキルを使わないAIは技術文書が得意で、v12でも新しい課題では勝ち越しと引き分けが半々です。nihongoが勝ちやすいのは、強さの違う指摘を分けて書くレビュー、表にした方が引きやすいAPI仕様、直しすぎの検査です。負けやすいのは、事実を箇条書きにまとめた方が早く読める障害報告です。

## 推敲用に作られた別の公開スキルとの比較

AIが書いた日本語を推敲するために作られた別の公開スキル（2026年11月時点の最新版）とも比べました。相手のスキルは、付属の検査スクリプトも手順どおりに動かしています。

| nihongoの版 | 課題 | nihongo | 別のスキル | 引き分け | 意味が崩れた数（nihongo / 別のスキル） |
|---|---|---|---|---|---|
| v10 | dev 16題 | 13 | 1 | 2 | 0 / 0 |
| v11 | holdout-1 6題 | 3 | 2 | 1 | 2 / 0 |
| v12 | holdout-2 6題 | 5 | 0 | 1 | 0 / 0 |

引き分けは、どちらも直しすぎの検査で原文をそのまま返した課題です。holdout-2 の1題（g02）は、相手のスキルが検査のあとに書き直した最終版ではなく、書き直す前の版で判定した可能性があります。

## 気をつけてほしいこと

- 判定したのはAIだけです。人が読み比べた結果ではありません。
- 直すAIも判定するAIも、同じ会社のモデルです。
- 1組の課題は6〜16題で、各課題を1回ずつしか直していません。同じ依頼でも、AIは毎回まったく同じ文を書くわけではないので、数題の差は偶然の範囲に入ります。
- 課題も変わってはいけない点の一覧も、作者側で作りました。
